# 统一数据核对规则

适用于报表、附注、底稿、台账及Excel/CSV/Word/PDF中的数据核对。由audit-report-checker统一执行，不再调用financial-data-check或audit-data-assistant。

## 1. 连续执行和必要提问

复用已确认的目标、范围和方案，简短说明做法后连续执行。文件、单位、期间和输出要求已有依据时不再询问；分批读取、发现差异、保存进度不增加确认节点。
能由原文或本地只读检查确认的事实自行查证。仅关键口径有歧义、需要变更目标或范围、扩大授权，或宿主要求确认不可逆操作时，集中说明依据和选项；只暂停依赖答案的部分，独立检查继续。
常规文件名和结构按用户要求及项目习惯确定。要求快些或只看摘要，不代表允许缩减实际检查范围。

## 2. 数据保真与完整读取

- 原始数字、公司和往来单位名称、账号、合同编号等保留原文，不编造、擅自脱敏或替换。明确授权的脱敏另按约定执行。
- 区分源数据和计算结果；计算结果注明公式、参与金额与来源位置。缺失、空白、横线、零及公式无缓存分别记录，不能自动互换。
- 登记文件全名、主体、年度或日期、合并/母公司/单体口径、币种和单位，以及实际工作表、页、表、行列范围。Word没有可靠页码时用章节、段落和表格位置，不编页码。
- 完整覆盖已选资料；分批记录已读、未读、未识别范围及跨批依赖。大文件不自动变抽样，受限时如实记录缺口，不把部分完成说成全部完成。

## 3. 先对齐再比较

1. 读懂多级表头、左右并排表、续表和列含义；按实际时点对齐，不凭“期初/期末”“本期/上期”或文件名年份拼接。
2. 记录每个期间取自哪份文件哪一列，沿用用户指定基准。未指定且多份版本相冲突时列出冲突，不认定最新文件天然权威。
3. 对应依据是主体、期间、业务含义和已确定的匹配键。名称相近、金额相等或位置相同不能单独证明对应；重名或一对多保留歧义，不自动合并或丢弃。
4. 单位明确时自行换算，保留原值、原单位、换算值和计算单位。单位缺失或矛盾时停止依赖项，不猜单位。保留原精度，不舍入到低精度后隐藏真实差异；按原文显示精度解释尾差，采用的容差须注明来源及适用单位，原始差额始终留痕。容差内相符不能写成原值完全一致。

## 4. 一致性与勾稽

- 同口径一致性：同主体、同日期或期间、同币种、同计量含义逐项比较。差额统一注明A值减B值；接口如输出绝对差额，另留方向说明，不改写接口字段含义。
- 跨期：上年期末对下年期初，上年发生额对下年比较期，分别核对。遇到追溯调整或重述，原报数、调整额、重述数分列；有依据才验算桥接，无依据列待核实，不凭差额补出调整数。
- 表内、表间勾稽：声明实际公式和不重叠范围，区分余额、准备、净额及金额、比例。不拿自身对自身验证，不重复计入“其中”、小计和其明细。
- 合并与单体不是同口径金额直接相等的关系。先确定合并范围和抵销、调整依据；缺资料不能把单体简单相加与合并数的差额认定为错误，也不能宣称完成合并抵销检查。
- 明细、台账、银行对账等不含四表时，只检查实际适用记录与关系，不虚构报表。复用已有可靠工具，专业判断由当前agent完成，算术交确定性工具；不要求纯手工，不强制切换外部模型。

通用数据源使用实际支持该格式的工具读取，例如CSV使用标准csv模块或宿主读取工具，保留原始行列和来源。不能把CSV直接交给只支持Word/PDF/Excel的报告解析入口，也不因没有对应解析器就假称已经核对。

## 5. 逐项留痕与交付

每项至少记录：项目、主体与期间、A/B文件全名、双方实际位置、原值及单位、必要换算与公式、差额、状态、依据和缺口。逐项记录一致、差异、仅A有、仅B有、待核实或未执行；与程序正式状态的对应写入依据，不另造程序无法识别的状态。
默认聊天说明范围、数量和差异重点，完整逐项记录进入交付文件。用户只看差异不等于漏查或销毁一致项；要求聊天展开全部时按其要求提供。
先列事实和不符关系；要求原因分析或勾稽判断时依据资料解释，区分已证实事实、假设和待补资料。纯数字核对不擅自扩展到舞弊或审计意见。
同源差异说明关联，不重复包装为独立错误。统计应检、已检、差异、仅一侧、待核实和未执行的实际数量；缺完整范围清单和检查记录不能声称全部一致。

## 6. 文件保护与失败处理

原始资料默认只读，结果另存；修改已有文件前按宿主规则备份校验。每次写入立即回读，发现乱码或错误停下修复。删除只按用户确认的精确清单使用Windows回收站。
读取失败先使用现有可靠工具或提取可读部分，保留失败原因与范围。无法取得的值标缺失或未执行，不补零。图片由当前agent核实，上传外部服务须有相应资料范围授权。
