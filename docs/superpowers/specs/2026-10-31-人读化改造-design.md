## 一、问题根因定位（已实查）

| 毛病 | 根因 | 位置 |
|---|---|---|
| 「凭什么说错」是底稿语言 | 导出层直接清洗粘贴 review.basis，不做重写 | export_report.py `_basis`/`_reason` |
| 标题是内部叫法拼盘 | 标题由规则名/依据拼接，不构成「结论一句话」 | `_title` |
| 假错误存活 | 旧结果条目引用隐藏表（表8=现补表）；导出层只按「条目自身 table_id」剔除，且归并时把可见条目和隐藏条目的差异混在一起组卡 | `_cards`/`_mismatches`/`_hidden_table_ids` |
| 碎尾数、数据流上表 | 「原文」栏直接拼行文本，金额不经人读格式化 | `_original`/`_amount` |
| 定位失效 | 大范围 row_range 直接输出；无对照位置 | `_location` |
| 甩锅建议 | 从依据里正则抠「需/请」句，或套固定模板 | `_suggestion` |
| 隐藏行/列照读 | 取数层只跳过隐藏工作表 | parse_report.py `_process_xlsx` |

## 二、候选方案

### 方案 A：展示层模板重构（推荐）

七个栏目全部由**结构化数据**（calculations 的规则名、期望/实际/差异、表行引用）组装；review.basis 只在「通读发现」类（无计算数据）时作为素材，且必须拆句重写。取数层补齐隐藏行/列跳过。

- 优点：直击根因；对旧 results.json 立刻生效（不重跑复核也能重出报告）；本地脚本不调模型，符合技能契约；可测试性强。
- 缺点：无计算数据的问题改写质量依赖句法处理，需「一分钟测试」人工兜底；模板句式写不好会僵硬。

### 方案 B：改写入端，让 AI 终审时就写人话

- 优点：治本。
- 缺点：改不了已有 results.json（本次验收恰恰要用旧结果重出）；「怎么写依据」是模型行为，约束不稳；超出「只改展示层」的既定范围。**不做**。

### 方案 C：导出时调模型翻译底稿

- 缺点：直接违反技能契约「本地脚本不连接其他 AI」。**否决**。

### 方案 D（补充决策）：来源漂移的诚实放行

真实源文件 04附注 在复核后被重新保存（正文比对无实质差异），`verify_sources` 会拦截重导出。用户明确要求「不重跑、用机器信息重排」。

- 决策：给 export_report.py 加显式开关 `--allow-source-drift`：列出漂移文件、警告后放行，并在技术留痕页写明「结论基于{日期}版资料；漂移文件及比对说明」。默认行为不变（继续拦截）。
- 这是「刻意偏离明显路径」：防止有人把旧结论当新结论用，又不挡住用户明确要求的重排。

## 四、七栏目内容规格（渲染层）

| 栏目 | 数据来源 | 规则 |
|---|---|---|
| 问题（一句话） | 差异数据或 issue_title | 「A 比 B 多/少 X」句式；无差异的用通读发现首句；禁内部编号；一主题一条，①② 疑点拆条 |
| 严重程度 | review.severity 优先，状态兜底 | 致命/重要/细节＋处理要求短语 |
| 错在哪 | 表元数据＋行标签 | 文件＋具体节/行/表名＋对照位置；行号只在有行标签或小范围时输出 |
| 核对了什么 | 规则名转自然句 | 「A 应该等于 B」→「……应该等于……」 |
| 差多少 | expected/actual/difference | ≥1 万元用「X.XX 万元」，否则元；浮点先归一到分；无差异写「不适用」 |
| 凭什么说错 | 结构数据组装 | 固定三句：核对方式、关键差异、判断；无数据时拆依据句改写；归并句式「本项由 N 条同类记录归并」 |
| 怎么改 | 状态＋差异数据 | 确认错误：改哪、改到什么程度、改完怎么复查；待核实：核实什么、在哪里核实；禁单句「请项目组确认」 |

## 五、隐藏内容与假错误处理

1. **取数层**（parse_report.py）：隐藏工作表（已有）＋隐藏行＋隐藏列一律跳过；pending 登记提醒。
2. **导出层**（export_report.py）：
   - 扫描源工作簿的 sheet/行/列隐藏状态，与提取表行号/列号对齐；
   - 条目自身 table_id 隐藏 → 不进问题清单，转提醒；
   - 条目内差异行引用隐藏表 → 剔除该行；剔完无剩余 → 整条转提醒；
   - 因隐藏来源造成的「确认错误」→ 计入「已排除误报」，一句话说明。
3. **提醒范式**（进概览页，不进问题清单）：情况（藏了什么、在哪）→ 处理（为何不算报出资料、核对结论如何）→ 建议（确认是否删除）。

## 六、错误处理与边界

- 提取表缺失/行号越界：定位退化为「文件 · 节/表名」，并在技术留痕留记录，不猜行。
- 差异字段缺失（expected/actual 为 None）：差多少写「不适用」，依据仍三句话结构。
- 归并条目：只归并同规则同文件的记录，归并后必须写影响面概括。
- 输出保护（不覆盖源文件/结果文件）维持现状。
